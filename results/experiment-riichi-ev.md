# リーチ判断の実測表を、使える形にする

## 出発点

`mj/riichi_ev.py` は「テンパイ状態から局がどう終わったか」を
(待ち枚数, 残り巡数, リーチか) 別に数えた表を持っている。97セル・12352標本。
作ったまま **打ち手からは一度も参照されていなかった**（grep で0件）。

繋ごうとして、先に一つ確かめた。

## その表は因果ではなかった

表は **エージェント自身の判断が作った状態** を数えたもの。
同じ (待ち枚数, 残り巡数) のセルの中でも、リーチした手とダマにした手は
打点も形も違う。打ち手は「打点が足りているとき」「待ちが狭いとき」に
ダマを選んでいたので、**ダマ側の成績が実際より低く出る**。

リーチの可否を 1/2 の確率で決めて測り直した（3000局・13617標本）。
セルの中で両側の分布が揃うので、比べられるようになる。

| 待ち | 残り巡 | 偏りあり（差） | 無作為化（差） | |
|---|---|---|---|---|
| 2-3枚 | 3-5巡 | +286 | **−197** | 逆転 |
| 2-3枚 | 6-8巡 | +237 | **−437** | 逆転 |
| 2-3枚 | 12-14巡 | +442 | +1456 | |
| 4-5枚 | 6-8巡 | +852 | +212 | |
| 4-5枚 | 9-11巡 | +423 | +745 | |
| 6-8枚 | 0-2巡 | +901 | **−311** | 逆転 |
| 6-8枚 | 6-8巡 | +2247 | **+1285** | 半分以下 |
| 6-8枚 | 12-14巡 | +3220 | +2261 | |

（差 ＝ リーチのEV − ダマのEV、単位は点。15セル中3セルで結論が逆転）

**偏りのある表をそのまま繋いでいたら、リーチを過剰に勧める打ち手になっていた。**
ダマ側が弱く見えるので、リーチの優位がどのセルでも水増しされている。

読み取れること:

- **待ちが広い（6-8枚）＋まだ巡目がある → リーチが明確に得**（+719〜+2261）
- **待ちが狭い（2-3枚）→ リーチの優位は小さいか、マイナス**
- **残り0-2巡 → どの待ちでもリーチはマイナス**（−272 / −391 / −311）
  リーチ棒1000点を払って、和了る回数が足りない

## 繋ぎ方 — 拒否権だけにする

表は (待ち枚数, 残り巡数) だけで引くので、**その手の打点を見ていない**。
「曲げたほうが得」と言われても平均の話でしかないので、**曲げさせる方向には使わない**。

逆に「ダマのほうが明確に得」と出たセルは、打点によらず成り立つ場況
（終盤・狭い待ち）なので、そこだけ止める。

```python
if st.riichi_ev_veto:
    adv = riichi_ev.advise(width, 18 - view.turn, dama > 0,
                           path=riichi_ev.RANDOMIZED_TABLE)
    if adv is not None and adv["差"] <= -st.riichi_ev_margin:
        return False
```

`riichi_ev_margin = 200`（点）。`make_best()`（かなめ）で有効にした。

## いまの効果

600局・同一種:

| 拒否権 | 局 | リーチ宣言 | 局あたり | 和了 | 流局 |
|---|---|---|---|---|---|
| なし | 600 | 651 | 1.085 | 463 | 141 |
| あり | 600 | 619 | 1.032 | 468 | 134 |

**リーチ宣言が4.9%減る。和了と流局には差が出ていない。**

600局で順位や収支の差は測れない（同型2人が6000半荘で 0.018 離れる環境）。
採用の根拠は結果側ではなく、**無作為化した測定で該当セルがマイナスと出たこと**。

## 残っていること

- 10000半荘の検証。いまは「悪化していない」ことしか言えていない。
- 無作為化した表は **いまの打ち手の集団に対して** 測ったもの。
  全員が拒否権を持つと場が変わるので、採用後に測り直す必要がある。
- `riichi_ev_margin` は振っていない（200点は「セルの標準誤差より大きい」
  という目安で置いただけ）。
