# 上達ロードマップと振り返り

## 振り返りの手順

1. **結果（順位）は最初に見ない**。判断の質だけを見る。
   順位から遡ると、放銃した打牌を全部悪手だと錯覚する。
2. 気になった局面を **2〜3個だけ** 扱う。それ以上は身に付かない。
3. それぞれを3分類する。
4. **今日の1点**を選んで終わる。

情報が足りなくても、**まず分かる範囲で分類と仮の結論を出してから**、
最後に「これが分かればもっと正確に言える」という形で1つだけ聞く。
先に質問して終わると、振り返りが完了しないまま流れてしまう。

## 悪手の3分類

| 分類 | 内容 | 直し方 | かかる時間 |
|---|---|---|---|
| **A. 牌効率** | 受け入れの数え間違い、ブロック選択のミス | 知識で直る。問題集を回す | 数週間 |
| **B. 押し引き** | 押すべきで降りた、降りるべきで押した | 基準表の暗記で直る | 1〜2ヶ月 |
| **C. 場況読み** | 危険度の見誤り、テンパイ気配の見落とし | 経験で直る | 数ヶ月〜 |

- **Aが多いなら** 問題集。`mj.py discard` で答え合わせしながら数をこなす
- **Bが多いなら** 基準表（`push-fold.md`）を暗記する。表を見ずに言えるまで
- **Cが多いなら** それは悪いことではない。AとBが片付いた証拠なので、打数を増やす段階

## 週次の見方

段位ptの推移は **週単位** で見る。日単位は分散に振り回されて判断を誤る。

常に見る指標は **4着率** だけ。**20%を切っているか** が雀聖到達のほぼ唯一の指標。

| 指標 | 見る頻度 | 目安 |
|---|---|---|
| 4着率 | 毎週 | 20%未満で雀聖圏 |
| 和了率 | 月1 | 21〜23% |
| 放銃率 | 月1 | 11〜12% |
| 副露率 | 月1 | 30〜35%（極端でなければよい） |
| 立直率 | 月1 | 18〜21% |
| 平均和了打点 | 月1 | 6000〜6500 |

**放銃率が低すぎる（10%未満）のは降りすぎ**の可能性がある。
和了率とセットで見る。放銃率を下げるだけなら誰でもできる。

## 牌譜検討ツール

| ツール | 特徴 |
|---|---|
| **MAKA** | 雀魂公式・無料（1日の回数制限あり）。対局後の牌譜画面から即解析 |
| **Mortal** | 無料。牌譜URLを貼るだけ。打牌ごとの推奨スコアと **pt損失** が出る |
| **NAGA** | 有料・天鳳中心（拡張機能で雀魂も）。一致率と悪手率の推移を追える |

### 使い方の注意

**一致率そのものを目標にしない。** 強いから一致率が高いのであって、逆ではない。
一致率を上げようとすると、AIの真似をするだけで判断の理由が身に付かない。

見るべきは **「pt損失の大きい打牌がどこに集中しているか」**。
損失の大きい5手を見れば、A/B/C のどれが弱いかがすぐ分かる。

雀聖層の目安は Mortal で **一致率 53〜55%、悪手率 8〜9%**。

## 局面をまとめて診断する — `mj.py review`

振り返りたい局面を1つ渡すと、結論・形・場況・着順条件・次点との差を
まとめて出す。個別のコマンド（`discard` `wait` `danger` `oorasu`）を
別々に叩く手間が要らない。

```bash
python3 skills/mahjong/scripts/mj.py review 3456778m234p55s99s \
    --dora 3s --turn 8 \
    --river "1m9p東南5s7m" \
    --visible "1m9p東南5s7m2p3p3s" \
    --scores 24000,25000,25500,25500 --me 0 --dealer 3
```

| 引数 | 意味 |
|---|---|
| `--visible` | 場に見えている牌ぜんぶ（全員の河・副露・ドラ表示牌）。待ちの実質枚数に効く |
| `--river` | 警戒する相手の河。**リーチ後に他家が切って通った牌も足す**（現物なので） |
| `--dora` | ドラ表示牌（ドラそのものではない） |
| `--scores --me --dealer` | 着順条件を出したいときだけ |

待ちの表示には「残り◯枚」に加えて **「山に約◯枚」** が出る。
残りのうち何枚が山にあって、何枚が相手の手の中かの目安
（`wall-reading.md` の実測値）。**山に多い牌ほど出てこない**ので、
ツモを狙うのか出和了りを狙うのかで読み方が変わる。

## 出題器 — 自分で反復する

`mj.py drill` が **実際の対局から拾った局面**で問題を出す。
答えは別コマンドなので、先に問題だけ見て考えられる。
`--seed` が同じなら同じ問題が出るので、間に時間を置いて再挑戦できる。

```bash
# 何切る（受け入れが割れる局面だけを選んで出す）
python3 skills/mahjong/scripts/mj.py drill --kind discard -n 5 --seed 1
python3 skills/mahjong/scripts/mj.py drill --kind discard -n 5 --seed 1 --answers

# リーチ者への打牌。どれが一番安全か（答えには実際の待ちも出る）
python3 skills/mahjong/scripts/mj.py drill --kind danger -n 5 --seed 1

# 相手はテンパイしているか（鳴いている相手を主に出す）
python3 skills/mahjong/scripts/mj.py drill --kind tenpai -n 5 --seed 1

# 山読み。見えている枚数が同じ牌のうち、山に濃いのはどれか
python3 skills/mahjong/scripts/mj.py drill --kind wall -n 5 --seed 1
```

| 種類 | 鍛えられるもの | 答えの根拠 |
|---|---|---|
| `discard` | 牌効率 | 受け入れ枚数（機械的に決まる） |
| `danger` | 押し引き・危険度 | 相手の**実際の待ち**が出る |
| `tenpai` | 河読み | 相手の**実際のシャンテン**が出る |
| `wall` | 山読み | 山の**実際の中身**が出る |

`danger` と `tenpai` は、シミュレータだから答えが分かる問題。
実戦では絶対に答え合わせできないので、**ここでしか練習できない**。

## 練習メニュー

### 毎日（10分）

- **`drill --kind discard -n 5`**。受け入れ最大を当てる
- **`drill --kind tenpai -n 3`**。鳴いている相手のテンパイを当てる
- 前日の対局から **1局だけ** 振り返る

### 毎週（30分）

- 4着になった半荘を1つ選び、**ラスになった原因の局を1つ特定する**
- 押し引きの基準表を見ずに書き出す（暗記の確認）
- 4着率をチェック

### 毎月

- Mortal / NAGA で牌譜を解析し、**pt損失の大きい5手** を見る
- A/B/C の内訳が変わったか確認する
- 統計（和了率・放銃率・副露率）を見る

## 段階別の課題

### 雀傑 → 雀豪

1. **ベタオリを覚える**。降りると決めたら降り切る
2. **先制リーチを打つ**。ダマにしすぎない
3. **役なしテンパイで鳴かない**

### 雀豪 → 雀聖（現在地）

1. **押し引きの基準表を体に入れる**。ここが最大の差
2. **一向聴の質を区別する**。「1シャンテンだから押す」をやめる
3. **オーラスの条件計算を間違えない**
4. **4着率を20%未満にする**

### 雀聖 → 魂天

1. 場況に応じた危険度の補正（染め手・トイトイ・ダマ）
2. 手出し/ツモ切りの記憶
3. 押し引きの微差を着順で調整する

## 声かけの温度

反省は続かないと意味がない。責めるためのものではない。

- できていた判断は **「それは正しい」と明言する**
- 正しく押して放銃した局は、はっきり **「その放銃は正解」** と言う。
  そこを曖昧にすると、次から押せなくなる
- 一度に3つ以上の課題を出さない。**今日の1点**を選ぶ
- 1半荘の結果から実力を語らない。判断の質と結果は **100半荘単位** でしか結びつかない
